\section{Dataset and Preprocessing}
\label{sec:dataset}

\subsection{Raw Data Overview}
The project uses a multivariate water-network dataset with 1,000 time-stamped
records collected from multiple sensors. Each record includes pressure,
flow rate, temperature, sensor ID, and binary leak status. Burst-related
samples are excluded to keep the task focused on leak detection.

Exploratory analysis confirms that leak events are rare at row level, and that
class imbalance remains present after windowing. This motivates careful split
strategy, calibration, and threshold analysis in later sections.

\subsection{Feature Engineering and Windowing}
The modeling pipeline uses six features per timestep:
\begin{itemize}[leftmargin=*]
    \item Pressure (bar)
    \item Flow Rate (L/s)
    \item Temperature (\textdegree C)
    \item Pressure delta
    \item Flow z-score (sensor-wise)
    \item Pressure/flow ratio
\end{itemize}

Sliding windows are built per sensor using:
\begin{itemize}[leftmargin=*]
    \item Window size: $W = 20$ timesteps
    \item Step size: $S = 5$
\end{itemize}

The resulting arrays used in this report are:
\begin{itemize}[leftmargin=*]
    \item Training windows: $125$ (leak windows: $41$, rate: $32.8\%$)
    \item Test windows: $39$ (leak windows: $11$, rate: $28.2\%$)
\end{itemize}

A calibration subset is drawn from training data only for early stopping and
operating-threshold selection, while the test set remains untouched for final
reporting.
